# v1.2.21: conservative review and guidance

Base: `c1b7f32e9a1a578c896271a43b2efccbee228a26` (v1.2.20 source metadata).
The external review was a static v1.2.19 review, not a reproduced device test.
Severity labels and sample patches are not automatically accepted.

## Product boundary

Keep the successful single-point/route interaction, retarget generations,
background leases, cellular transaction, and build-once promotion flow.
Add an optional Settings guide: native topic list and numbered detail pages,
Traditional Chinese and English, offline text, no onboarding gate, account,
analytics, or simulated device-session demonstration code.

## Deferred or rejected

- S1/B6/B13: credential/log exposure and mutating pairing getters are legitimate
  concerns. Existing Documents placement is an intentional import route.
  Changing/migrating/deleting trust files needs a dedicated, failure-safe migration
  and physical import/locked-device checks; this release does not silently remove
  that path. The guide warns that pairing files are trust credentials and must not
  be shared. This is a remaining risk, not a claimed security fix.
- B1/B2/B4/B12: possible FFI lifetime/concurrency issues need a scoped reproduction
  and lifetime audit. Adding semaphore timeouts without ownership cleanup can
  introduce use-after-free. Do not replace device transport ownership or guess
  whether a microsecond delay intended milliseconds.
- S2/B5: DDI download pinning/manual retry merits separate verification. Do not
  replace the explicitly chosen optional best-effort behavior with a mandatory
  consent/download prerequisite.
- S3: diagnostics redaction deserves structured-schema/value handling and a
  dedicated export audit. The suggested sample allowlist is not proof of safety.
- S4/S5/S6/S7: Health metadata, document-picker workaround, test transaction IDs,
  and broad pipeline pinning are outside the bounded user-flow patch. Keep actual
  HealthKit capability messaging and exact-artifact hash/provenance verification.
- U3: do not infer VPN availability solely from network type. No invented health
  flags or replacement readiness state machine.
- U4/U5/U7/M8: preserve deliberate prior product choices: 0.1 km/h adjustments,
  replacement speed entry, silent accidental map touches while playing, immutable
  playback draft, closed/infinite defaults, and background keepalive ownership.
- M2/M3/M5: failed writes/clear do not prove real GPS restoration. The proposed
  `idle` transition or automatic old-coordinate write can misrepresent location
  or race a newer user command. Defer these to a dedicated state/evidence design.
- M6/M7/M9/M11 (remaining): do not change bootstrap preflight, speed-default
  semantics, pending recovery timeouts, or concurrent library mutation semantics
  without specific behavioral tests and a separate scope.
- U8/U9/U10: avoid reorganizing Settings, the map, tab bar, or toast architecture.
  The guide explains the current locations and stop/restore distinction.
