# RouteLocation v1.2.15 UI / UX plan

## Scope

This release is a presentation and interaction polish pass. The proven
pairing, LocalDevVPN, RemotePairing/RSD/DVT, prepared-session, Cellular
Assisted bootstrap, PlaceInfoResolver, and route-recovery services remain
unchanged. No new network or device protocol is introduced.

## Current owners

- `MapHomeView` owns the primary map interaction and the route draft card.
- `MapSelectionView` owns the classic/quick map variants and coordinate entry.
- `PlaceFloatingCard` owns selected-place presentation and reverse-geocoded
  local time details.
- `RouteFloatingCard` owns saved-route preview and active playback controls.
- `MyPlacesView` owns favorite locations; `MyLibraryView` owns recent locations
  and the library section switcher.
- `RouteLocationModel` owns selected/active coordinates, persistence, route
  actions, and application-facing simulation commands.
- `RoutePlaybackEngine` owns the monotonic playback clock and live speed rebase.
- `PlaceInfoResolver` owns debounced, cached, serialized reverse geocoding.
- `SettingsView` and `SetupDiagnosticsView` own setup guidance and developer
  diagnostics; DDI remains available there but is not a core location blocker.

## Shared components and state

- Use a fixed two-state `MapBottomCardExpansion` (collapsed/expanded) with a
  spring snap gesture. The map remains the interactive surface; this is not a
  modal sheet.
- Use `RouteCoordinate` as the source of truth for selected and active
  coordinates. Active-card copy/favorite actions always read
  `RouteLocationModel.activeSimulatedCoordinate`.
- Add reusable country-code flag formatting, display-density preference, and
  centralized playback-speed bounds without adding a new framework.
- Keep PlaceInfo in memory/persistent cache through the existing resolver and
  reuse the same presentation/timezone helpers for favorites and recents.

## Interaction changes

- Selected and active map cards keep their primary and icon actions visible in
  the collapsed state and reveal address/timezone detail when expanded.
- Coordinate entry becomes a compact quick-entry sheet with an inline,
  user-initiated Paste control and keyboard-safe actions.
- Route editing uses native controls with one prominent Start action, native
  segmented route mode, compact speed +/- controls, and a low-frequency Menu
  for clear/undo actions. Favorite management stays in My > Routes.
- Active route playback presents a compact status/player card and disables
  speed mutation while reconnecting. Existing `setSpeed(_:)` distance rebase is
  reused.
- My > Places and Recent share one persisted compact/detailed display setting.
  Recents gain single-delete, context actions, and destructive clear-all
  confirmation.
- DDI is described as optional developer tooling for the core RouteLocation
  path; mounting controls remain available under developer diagnostics.

## Data and persistence

No destructive schema change is planned. Existing timestamp migrations and
PlaceInfo cache persistence remain backward compatible. The display-density
choice is a small UserDefaults/AppStorage preference. Recent deletion updates
the existing local recent list only and never touches favorites.

## Test strategy

Add deterministic tests for speed bounds/continuity, card state transitions,
active-coordinate ownership, country flags, display-density persistence,
recent deletion/clear semantics, parser and quick-entry invariants, and the
existing retained-session/recovery regressions. The existing PlaceInfo and
recovery tests remain the source of truth for those services; no real
CLGeocoder, Shortcut, DVT, or clipboard access is used in unit tests.

## Device validation

The branch CI can validate Swift compilation, tests, archive, and IPA
metadata. A physical iPhone is still required to validate map-card gestures,
keyboard/safe-area behavior, active-coordinate copy/favorite, live speed
continuity, recents gestures, and DDI optional messaging during a real
location session.
