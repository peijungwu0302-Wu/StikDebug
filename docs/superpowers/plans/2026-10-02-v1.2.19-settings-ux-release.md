# RouteLocation v1.2.19 — Settings, UX, and Build-once Release Plan

## Baseline and constraints

- Base: `f84a13abb1cb842c96cc8009e7b521f778fd9969` (v1.2.18 source metadata commit).
- Preserve location simulation, route playback, tunnel, pairing, DVT/RSD, and retarget behavior.
- Release only the exact final feature-CI artifact after successful provenance verification and promotion dry-run.

## Implementation sequence

1. Add focused tests for centralized appearance/coordinate-display preferences, DDI readiness policy, and shared favorite ordering.
2. Implement optional/idempotent DDI preparation and non-blocking diagnostics; leave normal simulation preparation independent.
3. Add persisted appearance and coordinate-text-size enums, root-level color scheme, and shared read-only coordinate display.
4. Fix Route Player coordinate width without loosening its internal 4-point spacing; make Map favorite selection consume `sortedFavorites`.
5. Move Health Sync controls into a dedicated settings destination, expose actual capability/authorization/error status, and keep all controls out of the main Settings list.
6. Localize all new/changed user strings in Traditional Chinese and English; rewrite equivalent `README.md` and `README.en.md`; update app-level source metadata only.
7. Change IPA CI to build feature/PR and test-release refs only, preserving test-release behavior and avoiding main/tag production builds.
8. Add a promotion-only workflow with exact successful feature-artifact discovery, authenticated archive download, digest/IPA/metadata checks, dry-run, release publication, and source metadata commit.

## Verification gates

- Run focused Python/static validation and `python tools/validate_repository.py`; run `git diff --check`.
- Run XCTest only if Xcode is available; otherwise make no local XCTest claim.
- Push only the feature branch and wait for its full CI, recording the exact successful head, test totals, and artifact provenance.
- Review the complete diff after CI. Fast-forward main only to that exact tested SHA.
- Dispatch promotion dry-run for that SHA/version. Create the immutable tag only after dry-run passes.
- Verify promoted IPA hashes, release state/assets, SideStore source entry, README publication, older-version preservation, and clean final state.

## Release stop rules

Any base, test, provenance, metadata, dry-run, tag, publication, or source-update mismatch halts the release. Never use a latest-artifact fallback, rebuild during promotion, move a tag, or force-push.
