# RouteLocation v1.2.14 UX architecture

## Scope

v1.2.14 improves the user-facing flow from “choose a place → simulate” and
“restore real location → choose another place → simulate” while preserving the
v1.2.13 StikDebug pairing, LocalDevVPN, DDI, RSD/DVT, and Assisted bootstrap
implementation. No LocalDevVPN, NetworkExtension, IPv6, or release metadata
changes are in scope.

## Session state ownership

`LocationSimulationCommandQueue` remains the sole owner of production FFI
handles. `LocationSessionCoordinator` exposes application-level readiness and
activity separately: simulation activity (`idle`, `singlePoint`, `route`) is
independent from location-session readiness (`unavailable`, `preparedHealthy`,
`degraded`, `recovering`). UI and models consume snapshots rather than reading
FFI globals directly.

## Retained session lifecycle

Restoring real location calls a queue-serialized clear operation that clears
the simulated coordinate but retains adapter/handshake/RSD/location handles.
Explicit full cleanup, failed clear, failed prepared write, and permanent
transport errors release those handles. The next simulation first attempts the
retained prepared handle; failure invalidates stale state and uses the existing
v1.2.13 Assisted flow.

## Place information

`PlaceInfo` is a Codable, framework-neutral value containing coordinate,
display name, country, administrative fields, and timezone identifier. A
`PlaceInfoResolver` actor debounces selection, cancels obsolete work, uses
quantized in-memory and Application Support JSON caches, and allows one active
reverse-geocode request. Geocoding is enhancement-only and never blocks
simulation, route building, or saving.

## Coordinate input and route import

The existing `CoordinateImportParser` remains the single parser. It accepts
comma, whitespace, semicolon, labeled coordinates, and Google Maps long URLs.
Single-point entry is a compact keyboard-safe sheet with user-initiated
`PasteButton`. Route mode presents one chooser for a waypoint, multiline paste,
or file import; append/replace updates geometry immediately without autoplay.

## Favorites and recent locations

Favorite naming uses a reusable, case-insensitive, whitespace-normalizing
`UniqueNameGenerator` with independent location and route namespaces. Saving
opens a lightweight naming alert with a unique default and optional geocoder
suggestion. Recent locations record intent actions only, never per-tick route
frames; existing timestamp migrations remain backward compatible.

## Tiered route recovery

Playback recovery has explicit levels: (1) prepared-session retry, (2) bounded
normal reconnect without DataOff, and (3) user-consented Assisted recovery in
the foreground. Background level 3 freezes progress and persists a pending
recovery/notification instead of silently toggling cellular data. A single
recovery coordinator owns the transition and preserves exact traveled distance
and running/paused state.

## Connection UI and setup check

The map exposes only `可以使用`, `正在準備…`, or `需要處理`; protocol details
remain in Settings → Developer Tools. Setup Check reports only facts the app
can verify (pairing file, VPN, shortcut configuration, location readiness), and
uses neutral guidance for Developer Mode.

## Testing strategy

Pure logic is covered with deterministic Swift tests: parser formats, unique
names, place cache/debounce/timezone calculations, retained-session lifecycle,
route append/replace/no-autoplay, recovery tier transitions, timestamp
migration, and accessibility/localization key coverage. Device-only DVT,
LocalDevVPN, geocoder availability, keyboard, notifications, and background
execution remain explicitly physical-device validation items.

## Real-device validation

Validate Wi-Fi-off cellular Assisted one-tap, restore-and-warm reuse, fallback
after stale prepared handles, Taiwan/Japan/US reverse geocoding and DST,
coordinate paste/import preview, foreground consent and background recovery,
long playback speed/pause/reconnect, and actual accessibility/keyboard layout
on iOS 17.4+.
