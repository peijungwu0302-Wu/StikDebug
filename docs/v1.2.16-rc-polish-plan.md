# RouteLocation v1.2.16 RC polish plan

## Scope and starting point

This release is based on `origin/main` at `3c3b80a535455b19c6e32d367d8eae0f762c679d`, the v1.2.15 SideStore metadata commit.  It changes application-facing interaction only; the RemotePairing/RSD/DVT, LocalDevVPN, Cellular Assisted, warm-session, recovery-generation, and PlaceInfo single-flight implementations remain the source of truth.

## Current ownership

* `RouteLocationModel` owns selected/active coordinates, route draft state, saved-library state, simulation transitions, and persistence calls.
* `RoutePlaybackEngine` owns monotonic playback time, distance, lap calculation, speed rebasing, and route recovery.
* `MapHomeView` and `RouteMapView` own map presentation; `PlaceFloatingCard` and `ActiveSimulationFloatingCard` own the two-detent bottom cards; `RouteFloatingCard` owns planning/player presentation.
* `RouteModels` owns Codable route/favorite/recent values and display-sort policies.
* `RoutePersistenceStore` owns local JSON persistence and legacy migrations.

## Design decisions

1. A single-point retarget cancels the old hold task, writes the new coordinate through the existing service, and starts a new hold without clearing simulation or restoring GPS.  A failed write uses the already-existing bounded/stale-session recovery path.
2. `RoutePlaybackMode` keeps its legacy `.once` and `.infiniteLoop` Codable spellings and gains `.finite(Int)`.  Old files decode unchanged; open routes normalize to one pass.  Closed geometry remains `isClosedLoop`, independent from repeat count.
3. Map cards use overlay layout rather than a bottom safe-area inset so MapKit keeps a stable viewport.  Collapsing only changes information density; typography and primary-action hit targets remain stable.
4. Coordinate quick entry is presented by a small UIKit alert bridge.  Its text field has a real `UIPasteControl` as the trailing view; no clipboard read occurs during presentation.
5. Planning and playing cards are separate branches.  Planning exposes compact route settings in an overflow menu; playing exposes progress, lap, speed, pause/resume, and a player overflow menu.
6. Favorites use a persisted sort preference plus a persisted manual UUID order.  Distance sorting uses a deterministic straight-line distance only when a valid device location is available; otherwise it falls back to stable creation order.  Recent management remains independent and uses the existing serialized PlaceInfo resolver.

## Test strategy

Write deterministic tests before each production change.  Cover retarget ownership and hold cancellation, repeat Codable migration/open-route normalization, finite lap completion, speed continuity, manual/distance sorting and persistence, recent delete/favorite isolation, and parser/clipboard presentation seams.  SwiftUI layout is checked through pure state/helpers rather than pixel snapshots.  CI remains the authority for Swift compilation, tests, archive, IPA packaging, and Info.plist validation.

## Real-device validation required

The following remain unverified until a physical iPhone test: A→B retarget without restoring GPS, no map jitter, native alert paste/privacy behavior, planning/player layout, finite lap display, single keyboard Done, route overflow semantics, manual reorder and distance sorting, recent leading-swipe favorite, and Dynamic Type/Dark Mode behavior.
